# 自定义 RenPy 图形化文字游戏编辑器设计

> 本文档是持续维护的产品与架构规格。开发中确认的新要求、范围调整和架构决定应直接更新到本文档。

## 目标

基于自定义发行版的 RenPy 制作一款面向 Windows 和 macOS 的文字游戏创作工具。编剧在 Word 中完成剧本，编辑人员将剧本手动录入工具，组合资源和演出并直接运行测试。技术人员继续使用外部代码编辑器编写 RenPy/Python 扩展、互动玩法和无法图形化表达的逻辑。

工具取代 RenPy 启动器中的项目创作入口，同时保留新建项目、打开项目、最近项目、运行和打包等核心项目管理能力。

## 设计原则

- 图形编辑优先，代码可扩展。
- 界面以工作效率和信息层级为优先，采用克制的基础色、文本标签、图标和边框；不使用装饰性插画、动态背景或与任务无关的视觉特效。
- `.rpy` 是唯一的项目源文件，不维护平行的场景数据文件。
- 编辑器只重写其完全理解的线性演出语句。未知语句、复杂条件、Python 和插件代码保留为代码块，绝不自动改写。
- 项目资源放入规定目录，编辑器自动扫描，文件名直接作为资源名称。
- 项目内容使用相对路径，能够在 Windows 与 macOS 间直接打开。

## 平台架构与开发基线

项目只维护一套通用源码，不建立互相分叉的 Windows 和 macOS 功能版本。发布时从同一提交分别生成 Windows 和 macOS 两个发行包；两个发行包使用相同的项目格式、编辑功能和界面结构。平台差异集中在主修饰键、路径处理、文件选择、外部程序启动和发行包装层。

开发固定基于 RenPy 8.5.3，已确认本机 SDK 位于 `/Applications/renpy-8.5.3-sdk`，内部版本为 `8.5.3.26051504`，并同时包含 macOS 与 Windows 运行组件。该安装目录只作为本机开发输入，不在其中直接编辑，也不把其中约 353 MB 的运行库和生成文件提交到项目仓库。

Git 仓库保存自定义发行版的源码覆盖层、项目模板、构建脚本和版本锁定信息。开发脚本从指定的 RenPy 8.5.3 SDK 创建被 Git 忽略的工作副本，再把源码覆盖层应用到副本中运行和打包。SDK 路径可配置，构建过程不得依赖当前用户的绝对路径。macOS 功能在当前开发机验证；Windows 发行包必须在 Windows 真机完成最终验收后才能标记为已验证。

## 项目结构

新建项目生成固定的 RenPy 结构：

```text
项目目录/
├─ game/
│  ├─ script.rpy
│  ├─ story/
│  │  ├─ 00_prologue.rpy
│  │  ├─ 01_chapter_01.rpy
│  │  └─ ...
│  ├─ code/
│  └─ assets/
│     ├─ backgrounds/
│     ├─ characters/
│     ├─ cg/
│     ├─ bgm/
│     └─ sfx/
```

`story` 保存引子、章节、场景和分支。`code` 保存由技术人员维护的互动模块和扩展代码。`assets` 是只按文件夹扫描的资源库；编辑器不复制资源文件。

所有资源路径相对于 `game` 目录。资源文件名使用小写英文、数字、下划线和扩展名，禁止大小写冲突和不跨平台的字符。视频 CG 使用 `.webm` 作为团队标准格式。

项目目录名可以使用中文等 Unicode 字符和内部空格，但必须同时兼容 Windows 与 macOS：禁止路径分隔符、控制字符、Windows 非法字符与设备保留名，禁止以空格或句点结尾。资源文件名仍遵守更严格的小写英文规则。

新建项目内置采用 SIL Open Font License 的 Source Han Sans Lite，并将其设为默认文本字体，使中文剧本在 Windows 与 macOS 上无需依赖系统字体即可显示。字体文件及许可证随项目保存和打包。

## 项目主流程

```text
启动自定义 RenPy
  -> 项目中心：新建、打开、最近项目、运行、打包
  -> 进入项目工作区并扫描 assets
  -> 建立章节、场景、选择节点
  -> 参照 Word 剧本录入文本和演出
  -> 保存 .rpy
  -> 检查
  -> 使用同一份自定义 RenPy 运行测试
```

外部编辑器入口用于打开当前 `.rpy`、代码块或玩法模块。外部改动保存后，用户回到工具执行刷新，重新解析文件。

外部编辑器的可执行文件只保存在 RenPy 启动器偏好中；留空时使用系统默认应用。刷新会重新读取脚本、资源和 `gameplay_` 标签。当前场景预览先保存编辑内容，创建可被 RenPy 编译的 `game/visual_editor_preview.rpy`，以 RenPy warp 进入目标场景，并在游戏进程退出后删除；项目 `.gitignore` 和 `build.classify` 同时排除异常中断遗留的预览文件。第一版精简项目不包含完整的退出确认界面，因此关闭游戏窗口直接退出，不调用缺失的确认屏幕。

## 场景创作模型

场景以纵向演出事件列表为主，只有选择节点使用局部流程图。列表从上到下就是 RenPy 的执行顺序，每一行对应一项实际演出事件，而不是视频剪辑时间轴。编辑人员先添加主体，再给主体添加演出功能。

| 层级 | 内容 | 规则 |
|---|---|---|
| 场景 | 场景容器、全局视觉效果、默认环境 | 只有场景可以拥有全屏黑屏、白闪、抖动和模糊。 |
| 视觉主体 | 背景、角色、视频 CG | 背景构成环境；角色是可复用完整立绘；视频 CG 是独立播片。 |
| 文本主体 | 旁白、角色台词、叠加文本 | 普通对话使用全局对话框；叠加文本可单独定位。 |
| 音频附加 | BGM、环境音、音效 | 可附加到场景、文本或视觉主体。BGM 支持循环、停止和淡入淡出。 |
| 视觉附加 | 入场、退场、淡入、移动、缩放、滤镜、扭曲 | 附加到背景、角色、视频 CG 或文本主体。 |

第一版角色使用完整立绘资源组，不规定身体、服装、眼睛或嘴巴的拆分格式。角色添加到场景后，Inspector 从该角色目录中选择具体立绘文件，并配置位置、缩放、层级和附加功能。

每一个可编辑节点都包含备注字段，包括场景、背景、角色、视频 CG、文本、音频、视觉附加、互动节点、选择节点和分支选项。备注在 Inspector 中编辑，在时间线和流程图中以低干扰的备注标记提示，并在悬停或选中时显示全文。备注不影响运行效果，保存为紧邻对应 RenPy 语句的结构化注释，确保它与 `.rpy` 一同进入版本控制、跨平台移动和外部编辑。

视频 CG 在 Inspector 中配置文件、层级、位置、播放方式与结束行为：恢复原画面、停在最后一帧、或切换为指定的新画面。

### 事件分类和推进方式

事件分类不改变执行顺序，只决定新增菜单、资源选择与 Inspector 配置。主事件分为场景、背景、角色、视频 CG、文本和控制：

| 主事件 | 作用 |
|---|---|
| 场景 | 全局画面操作，例如黑屏、白闪、抖动和模糊。 |
| 背景 | 地点、天气和时间变体。 |
| 角色 | 完整角色立绘的显示、替换、隐藏和位置。 |
| 视频 CG | 全屏或嵌入画面的视频播片。 |
| 文本 | 角色台词、旁白和可自由定位的叠加文本。 |
| 控制 | 暂停、选择、互动模块和代码块。 |

视觉效果和音频是附加功能，显示为其主事件下的子项。视觉效果包括淡入、移动、缩放、滤镜和扭曲。音频包括 BGM、环境音和音效；音频可附加到场景、背景、角色、视频 CG 或文本，并配置循环、停止和淡入淡出。

每个事件还拥有推进方式：立即执行、点击继续、自动继续、等待视频、等待选择、等待互动模块返回或代码控制。背景、角色、音频和效果默认立即执行；台词与旁白默认等待点击；选择、互动和视频按其类型等待。编辑人员可显式添加暂停事件，设为等待点击或等待指定时长。

自动推进文本输出为带 `{nw=秒数}` 的 RenPy 文本语句，文字和对话框在设定时长内保持显示，时间到后自动继续。编辑器可读取旧版 `{nw}` 加数值 `pause` 格式，下次保存时迁移为新格式。定位视频使用非循环 `Movie`，等待视频以 Inspector 中记录的秒数生成数值 `pause`；结束行为保存为恢复原画面、透明结束或保留最后一帧。影音附加及其备注作为结构化 `visual-editor` 注释保存，同时生成标准 `play`、`stop`、`with` 和 ATL 语句。

编辑器预览提供开始播放、模拟玩家点击和运行到下一推进点。正式游戏保持 RenPy 原生点击推进、自动播放、跳过、回滚、存档和读档行为。

## 工作区交互

- 左侧项目树显示章节、场景、选择节点和代码块。
- 资源库显示扫描到的背景、角色、视频 CG、BGM 和音效。
- 中间舞台预览使用游戏设计分辨率。
- 下方演出事件列表按执行顺序显示主体和其附加功能，并支持拖动调整顺序。
- 右侧 Inspector 编辑当前选择对象的资源和参数。

Inspector 中每个可编辑字段的整个输入区都可用鼠标点击获取焦点，自动舞台刷新不得把焦点抢回其他字段。选中文本事件时，点击 Stage 中的文字画面会聚焦到 Inspector 的 Text 字段，随后的键盘输入会触发同一套自动预览刷新。

工作区必须作为覆盖启动器的全屏模态层显示。三栏宽度及间距的总和不得超过 RenPy 的虚拟画布，任何支持的窗口缩放比例都必须保留右侧 Inspector，启动器底部链接不得透出或覆盖编辑器。

视觉设计保持简洁：不使用装饰图片、渐变背景或非功能性动效。状态通过清晰的文字、有限的图标、边框、颜色和空白区分；资源缩略图只用于识别实际资源文件。

舞台支持直接操作。选中角色、视频 CG 或叠加文本后显示边框、锚点和缩放手柄。拖动改变位置，拖动边缘缩放，按住 Shift 保持比例，并吸附到画面中心、边缘和其他元素。位置保存为相对布局参数而非屏幕像素。

第一版舞台以 640 × 360 的编辑视口换算位置，但 `.rpy` 中只保存 `xalign`、`yalign`、`zoom` 和 `zorder`，不保存编辑视口像素。中心与四边在 8 像素范围内吸附，资源类型不匹配时拒绝分配。缩放统一保持原始宽高比；后续可以在不改变保存格式的情况下增加可调舞台视口。

启动器舞台预览从所选项目目录读取图片字节并交给 RenPy 解码，不把项目的绝对文件路径交给仅识别当前启动器搜索路径的图片加载器。切换或刷新项目时清空舞台图片缓存，确保外部替换的素材能够重新载入。

### 真实游戏画面自动预览

中央 Stage 的最终画面以当前项目自身的 RenPy 渲染结果为准。选择任一事件时，编辑器重建从场景开始到该事件为止的视觉状态，并由项目进程使用项目的设计分辨率、图片、字体、`gui.rpy`、`screens.rpy`、角色定义和样式生成一帧预览。文本事件必须通过项目实际的 `say` 界面或 RenPy 默认对话界面显示，因此姓名框、文字框、字体、字号、边距和位置与运行游戏一致。Stage 只负责按比例缩放渲染结果并叠加编辑选框，不重新模拟一套对话框。

编辑器根据内存中的场景模型生成临时渲染入口，不要求先保存正式 `.rpy`，也不改变正式剧情入口。临时入口只重放影响当前画面的安全事件：最近背景、当前仍显示的角色和 CG、位置与缩放、可静态应用的视觉附加，以及当前文本。此前的台词、等待、音频和控制流不重复执行；音频保持静音。选择、互动和不可理解的代码节点不自动执行，Stage 保留最近成功画面并显示无法静态渲染的原因。视频与转场截取稳定帧，不在 Stage 中完整播放。

每次切换场景、选择事件或修改可编辑字段后自动请求新画面。连续输入采用 300 毫秒防抖；同一时刻最多运行一个项目渲染进程。每个请求拥有递增代号，新修改到来时允许当前进程结束或终止，但旧结果不得覆盖较新的请求。渲染期间继续显示上一张有效画面，并在 Stage 中显示“正在刷新”；首次渲染时显示中性占位。

渲染进程在项目内创建可被 RenPy 编译的临时 `.rpy` 入口，在独立临时目录写入 PNG，再通过定时覆盖层于首个稳定交互帧截屏并退出。临时源码、截图、日志和编译缓存不进入项目版本控制或游戏发行包，正常结束和异常结束后都应清理。路径、进程终止和临时目录逻辑必须同时支持 Windows 与 macOS。

Stage 将项目设计分辨率等比缩放到可用视口，保留黑边，不拉伸画面。编辑选框使用相同的坐标换算覆盖在真实渲染帧上；拖动或缩放提交后立即请求下一帧，以实际渲染结果校准。渲染失败时保留最后一张有效画面，并显示简短错误、源文件与行号，同时允许用户继续编辑或打开外部代码。

普通对话框采用项目全局布局。场景可创建文本布局覆盖，并在舞台中拖动对话框位置。特殊字幕、回忆文字等使用可自由拖动的叠加文本主体。

## 分支、互动和存档

选择节点在局部流程图中展示。每个选项连接到一个后续场景，编辑器生成标准 RenPy 的 `menu`、`jump` 和 `label` 语句。条件选项可以在后续版本基于游戏变量控制显示或禁用。

选择提示、选项文字、目标标签、选项备注和稳定选项 ID 使用结构化注释保存。第一版局部图以紧凑的“选择 → 选项 → 目标标签”节点列呈现，允许新增、重命名、重新连接和删除选项；完整自由布局流程图不属于第一版范围。

互动玩法是时间线中的互动节点。技术人员在 `code` 中实现完整玩法模块，例如角色操控、搜查、道具和战斗。编辑人员只在 Inspector 中选择玩法入口，并把节点插入剧情。编辑器生成对玩法标签的 `call`，模块返回后按设定的场景或变量继续剧情。

编辑器仅把 `game/code/**/*.rpy` 中以 `gameplay_` 开头的标签列为可选玩法入口。项目模板用 `default gameplay_state = {}` 提供可存档、可回滚的原生状态容器，并提供写入 `persistent` 的解锁辅助函数；玩法模块仍可直接使用任何可序列化的 RenPy store 值。

存档、读档和回滚使用 RenPy 原生能力。互动模块必须把需要恢复的状态放在可保存的 RenPy 变量中。跨存档、跨周目保留的图鉴、结局和解锁状态使用 RenPy 的 persistent 数据。

## 输入与跨平台规范

编辑器统一使用“主修饰键”：Windows 为 Ctrl，macOS 为 Command。

| 操作 | 输入 |
|---|---|
| 滚动资源库和 Inspector | 鼠标滚轮或触控板双指上下滑动 |
| 横向移动时间线 | Shift 加滚轮或双指滑动，或拖动滚动条 |
| 平移舞台和流程图 | Space 加左键拖动 |
| 缩放舞台和流程图 | `+`、`-`、`0` 适合窗口 |
| 保存 | 主修饰键加 `S` |
| 运行 | 主修饰键加 `R` |
| 刷新资源与脚本 | 主修饰键加 Shift 加 `R` |
| 撤销与重做 | 主修饰键加 `Z`；主修饰键加 Shift 加 `Z` |
| 外部打开代码 | 主修饰键加 `E` |

所有右键菜单操作也必须有可点击的工具栏或 Inspector 入口，确保 Mac 触控板用户不依赖右键。

Windows 同时绑定 `Ctrl`，macOS 同时绑定 `Command`；保存、预览、刷新、撤销、重做和外部打开均保留可点击按钮。撤销历史在内存中最多保留 100 个编辑前检查点，重新打开或刷新项目时清空。按住 Space 拖动舞台背景只改变编辑视图偏移，不改变事件的相对坐标。

## 检查与测试

保存直接更新对应 `.rpy` 文件，并保留当前编辑会话的撤销与重做。检查功能在运行前验证：

- 缺失、改名或不可读取的资源；
- 不跨平台的文件名和大小写冲突；
- 空选择节点、未连接选项、重复标签和缺失互动模块；
- 外部改动后无法图形化理解的语句；
- RenPy 语法错误及其文件和行号。

测试入口包括从项目开头完整运行，以及从当前场景临时启动。后者用于快速检查舞台布局、文本框、音频、视频和特效，不改变正式剧情入口。报错优先关联到章节、场景和事件；无法关联时显示 `.rpy` 行号并提供外部打开入口。

## 实施范围

完整版本包含项目创建与打开、资源扫描、场景事件列表、背景、完整角色立绘、文本、视频 CG、BGM、环境音、音效、视觉效果、备注、直接操作舞台、推进方式、选择分支、互动模块插入、原生存档与 persistent 数据、外部代码编辑入口、跨平台输入、检查和运行测试。

复杂互动玩法本身仍由技术人员在 `code` 中实现；编辑器只插入和连接玩法模块。角色部件组合、自动 Word 解析和内置代码编辑器不在本次范围内。
